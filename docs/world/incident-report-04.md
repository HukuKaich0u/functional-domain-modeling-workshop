# 事故報告 第4号

| 項目 | 内容 |
| --- | --- |

| 関係者 | 基地長、電気主任、医務、地上管制 |

| 該当条文 | 第2条、第3条、第8条 |

## 事象1: 遮断盤の表示ラベルが系統区間として保存された

地上管制の旧端末から `EVA-0412` の開始承認が届いた。端末の送信処理は、
系統区間の識別子ではなく、遮断盤の画面に表示するラベル `PV07-LOCKED`
を `segmentId` の欄に入れていた。

作業管理システムの入力境界は値を検査せず、そのまま `ApproveEvaInput`
を作った。作業許可には系統区間として `PV07-LOCKED` が保存され、遮断
された区間を突き合わせることができなくなった。

## 事象2: 宇宙天気の報告が壊れた形で保存された

同じ端末から届いた宇宙天気の報告は、発令時刻が数値、警報レベルが
未定義の値、観測局の一覧が配列ではなく文字列だった。システムは報告を
検証せず、そのまま作業許可に保存した。フレア警報の有無を、この報告
からは判断できなかった。

## 事象3: 被ばく量が作業記録に残った

承認の判定に使う作業員2名の被ばく量が、作業許可の状態と作業記録の
payload に含まれていた。第1号の事象2と同じ経路で、共有ログから読める
状態だった。被ばく量は、今回の滞在で隊員がこれまでに浴びた放射線の量で
あり、個人の健康に関わる情報として医務が管理している。

## 直接の原因（システム）

- 外部からの入力を `any` として受け取り、検証せずに型付きの入力として
  扱っている
- 外部JSONの形を確認していない
- 被ばく量を平文の数値として状態に持ち、記録に出している

## 影響

- `EVA-0412` の承認をやり直し、遮断札と系統区間を再確認
- 共有ログから作業記録を削除

## 是正の方針

外部からの入力は `unknown` として受け取り、境界でスキーマ検証してから
型付きの入力にする。被ばく量は `Sensitive` で包み、判定でだけ取り出す。

# 事故報告 第2号

| 項目 | 内容 |
| --- | --- |
| 報告書番号 | 第2号 |
| 発生 | 前の昼、月面日第13日 |
| 場所 | 赤道発電所 PV-06、日の出基地エアロック |
| 作業許可 | `EVA-0415`（PV-06 接続部の補修）、`EVA-0416`（PV-06 点検） |
| 関係者 | 基地長、電気主任、作業員a、作業員b、地上管制 |
| 報告者 | 前任のシステム担当 |
| 該当条文 | 第2条、第6条、第7条 |

## 事象1: 装備点検の記録がないまま承認済になった

`EVA-0415` は、作業員aと作業員bの装備点検が記録される前に承認済になった。
基地長の端末は「開始を承認する」を申請済以外の状態でも押せる。承認の
処理は現在の状態を確かめず、`status` を `"approved"` に書き換えた。

作業員bはエアロックで酸素残時間を確認し、点検が未記録だと気づいて出発
を止めた。出発していれば、酸素残時間の確認なしに作業へ入っていた。

## 事象2: 完了した作業許可が再び承認済へ戻った

同日夕、完了した `EVA-0415` に対して地上管制の端末から開始承認が届き、
許可は完了から承認済へ戻った。作業記録には完了と承認済の両方が残り、
翌日の計画会議で、この許可の作業が終わっているかを記録から判断できな
かった。

## 事象3: 中止の理由が残らなかった

`EVA-0416` は地上管制の判断で中止されたが、中止の操作に理由が付いて
いなかった。翌日、同じ区画の点検を計画し直すときに、中止の原因が宇宙
天気だったのか、装備の不足だったのかを誰も答えられなかった。

## 直接の原因（システム）

- 作業許可の状態が任意の文字列で、遷移関数がどの状態からでも呼べる
- 状態ごとに必須の情報（点検記録、承認時刻、中止理由）が optional
- 中止の理由が省略可能
- 状態を追加したときの分岐漏れを検出する仕組みがない

## 影響

- `EVA-0415` の作業結果を確認するため、翌日に再点検を実施
- 中止の原因が不明なまま `EVA-0416` を再計画

## 是正の方針

作業許可の6状態を判別共用体で表し、遷移関数が許可された遷移元だけを
受け取るようにする。中止には理由を必須にし、状態の追加は表示の分岐で
コンパイルエラーになるようにする。

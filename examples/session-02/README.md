# Session 02: EventStorming と ROP で船外作業の中止を設計する

S2 は班ワークです。コードは編集しません。「船外作業が中止された」という一つの出来事から、依頼、業務ルール、集約、成功出力を逆算します。

このディレクトリは、S0 と同じ旧コードと事故を持つスナップショットです。EventStorming で確認する条件を、コードのどこが守れていないかと照らして読むために置いています。

```bash
pnpm demo:02
```

## 参加者が行うこと

- 誰が何を依頼したために、船外作業が中止されたかを逆算します。
- 中止できるのは誰か、作業許可の存在と現在状態、中止理由の条件を業務ルールとしてまとめます。
- 答えが揃わない点は Hotspot として残します。

条件は次の文へ揃えます。

> 地上管制または基地長が、出発前の作業許可だけを、理由を残して中止できます。

## EventStorming から ROP へ写す

- コマンドは業務ワークフローの入力です。
- 権限や状態の条件は、ワークフロー内部の業務ルールです。
- `EvaPermit` 集約の `abort` を内部のドメイン判断として呼びます。
- 成功出力は `PermitAborted` です。
- 失敗出力は `Unauthorized`、`PermitNotFound`、`InvalidPermitState` など、理由を区別できるエラーです。

現在状態の取得は入力側の Resolver へ、`PermitAborted` を受け取る作業記録の追記は出力側の Store へ置きます。中心の業務ワークフローはデータベースへ接続せず、入力からイベントか型付きエラーを返します。

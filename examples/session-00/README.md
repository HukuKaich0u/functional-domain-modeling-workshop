# Session 00: 引き継ぎ

これは、現在の作業許可の内容と操作ごとの作業記録を SQLite に残す、意図的に壊れやすい作業管理のスナップショットです。

帰還済みの作業許可を作業中へ戻せること、作業記録に作業員の累積線量が残ること、作業許可だけが変更されて記録が残らない場合があることを観察します。Session 00 では修正せず、Session 03 から Session 07 で状態、識別子、入力と機微情報、失敗、副作用と保存処理を順に改善します。

```bash
pnpm demo:00
```

`http://localhost:3000` で操作と事故を再現できます。SQLite ファイルは `examples/session-00/moonbase.sqlite` です。サーバーを停止して起動し直しても、現在の作業許可と作業記録は残ります。「デモを初期状態へ戻す」を明示的に実行したときだけ、最初の作業許可と作業記録へ戻ります。

## 事故を再現し、データベースに残った内容を確認する

画面の事故再現パネルで、想定外の状態、系統区間の取り違え、不正な宇宙天気の報告、失敗理由の取り違え、操作ごとに変わる時刻と記録 ID を順に確認します。その後、「現在の作業許可」「作業記録」「不整合の警告」を見比べます。現在の作業許可と作業記録が一致するか、作業記録に不要な機微情報が含まれていないかを確認してください。
